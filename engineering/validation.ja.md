# 追跡可能性と検証

**実行可能な要約。完全な表は[英語版](validation.en.md)。実行ケースは計画であり実接続の証拠ではない。**

| ケース | 検査する境界 |
|---|---|
| WF-T01–T02 | WF-01/07: 不存在、古い証拠、セッション変更で送信ゼロ。 |
| WF-T03–T05 | WF-02/03: 認証不明、未認証、対象拒否を区別し、主体等の不一致を拒否。 |
| WF-T06–T07 | WF-04/07: 承認なし、不一致、期限切れ、再利用を拒否。 |
| WF-T08 | WF-05: 応答文中の命令で権限を拡張しない。 |
| WF-T09–T10 | WF-06/08: 不確かな書込みを再送せず、秘密を漏らさない。 |
| WF-T11–T12 | WF-04/08: 正規化と時間・サイズ・再試行制限。 |

`valid-read` と `valid-write` は構造例だけである。`invalid-missing-asset` はスキーマで失敗する。`invalid-approval-binding` と `invalid-asset-denied` は構造上有効でも、それぞれ `APPROVAL_MISMATCH` と `ASSET_DENIED` で停止する。有効な受領例は書込み不確定の例である。人工時刻を用い、現在の証拠にしない。

各実行でケースID、改訂、ポリシー、環境、時計、入力ハッシュ、期待・実測状態、送信数、記録、レビュー者を保存する。バリデーターの版と日時形式検査の有無を明記する。構造検査、意味検査、認可された実接続検査を分離し、失敗や未実行を合格にしない。
