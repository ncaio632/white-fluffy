# 要件と信頼境界

**日本語の実行可能な要約。完全な仕様は[英語版](requirements.en.md)。設計案であり、実装や実接続の証拠ではない。**

接続済みという表示だけでは操作を許可しない。観測されたツール一覧、認証、対象資産への権限、書込みの明示承認を別々に判定する。広告、開発、業務メッセージという機能群は分離の概念であり、導入済みコネクターを意味しない。

| ID | 必須動作 |
|---|---|
| WF-01 | 完全かつ新しい一覧をセッションと記述子ハッシュに結び付ける。 |
| WF-02 | 認証済み・未認証・不明を区別し、秘密値を記録しない。 |
| WF-03 | 主体、機能群、対象、操作が一致する権限を確認する。 |
| WF-04 | 書込みは対象、目的、操作、ペイロードハッシュ、有効期限が一致する明示承認を要する。 |
| WF-05 | リモート文章を命令と扱わず、効果不明なら停止する。 |
| WF-06 | 成功・失敗・効果不明を区別した秘匿済み受領記録を残す。 |
| WF-07 | セッション等の変更で証拠を無効化し、承認は一度だけ消費する。 |
| WF-08 | 時間、サイズ、再試行回数を制限し、不確かな書込みを自動再送しない。 |

合成プロファイルの証拠有効期間は五分を提案する。運用担当が失効特性と時刻ずれ許容を別途決める。ハッシュはキーを整列した空白なしUTF-8 JSONのSHA-256とし、重複キーや非整数を拒否する。スキーマ適合は権限、時刻、ハッシュの正しさを証明しない。
