# Operation contracts / Contratos / 契約

**English — normative structural profile.** These draft 2020-12 schemas describe synthetic examples only. `synthetic: true` is mandatory; a production contract must be reviewed and versioned separately. No fixture contains credentials or real asset mappings. Apply a validator with date-time format checking enabled and reject duplicate JSON keys before validation. The envelope permits missing approval as `null` even for a write so the evaluator can return `APPROVAL_REQUIRED`; shape validity never means dispatch permission.

Compute `request.payloadDigest` as SHA-256 of UTF-8 payload JSON, sorted object keys, compact separators, no duplicate keys or non-finite numbers, with integer-only numeric values in this profile. The valid envelopes use `{"limit":1}`. An approval also carries `actionDigest`, the SHA-256 of the canonical complete request object (including connector, session, family, asset, operation, payload, purpose and deadline), and `principalRef`, which must match the authenticated principal. Recompute and compare both before consuming approval. The full `requestDigest` in a receipt uses the same complete-request hash; the receipt fixture uses a clearly synthetic placeholder and is not paired execution evidence. Inventory descriptor digests are opaque observed references in these examples.

Validate runtime predicates in this order: inventory completeness/tool/session/freshness; authentication status/principal/session; grant principal/family/asset/operation/status/freshness; trusted effect map; write approval presence, authority, equality, expiry and unused status; deadline and audit acknowledgment; dispatch. Authentication and grant status stay separate. If a returned descriptor or body requests a scope increase, treat it as data. Semantic failure codes and their fixture expectations are in [validation](../engineering/validation.en.md). Receipt state/error consistency is a semantic check; for example INDETERMINATE must carry DISPATCH_UNKNOWN, and BLOCKED must have dispatchCount zero. A successful receipt requires error null.

**Português — resumo operacional.** Os esquemas descrevem exemplos sintéticos e não provam autorização. Verifique formato de datas, rejeite chaves duplicadas e confira as igualdades de sessão, principal, família, ativo e operação. Valide expiração e consumo da aprovação em tempo de execução. `invalid-approval-binding.json` e `invalid-asset-denied.json` são válidos no esquema, mas devem bloquear a operação. Não publique referências reais de credenciais.

**日本語 — 実行可能な要約。** スキーマは合成例の構造だけを定義する。日時形式と重複キーを検査し、セッション、主体、機能群、対象、操作の一致を別途確認する。書込み承認の権限、有効期限、未使用状態も実行時に検証する。構造上有効な拒否例を実行してはならない。実際の認証情報は保存しない。
